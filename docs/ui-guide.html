SuryaSetu UI Guide

How the screens work, and which file does which job. For Partner B and anyone joining the ui branch.

Run it

npm run dev      # from the repo root
                 # API on http://localhost:8000
                 # UI on http://localhost:3000

First time on a machine, install and seed:

copy .env.example .env      # then set JWT_SECRET to a long random value
python -m venv ..\.venv-api
..\.venv-api\Scripts\pip install -r requirements-dev.txt
cd ui && npm install && cd ..
npm run db:seed -- --reset

Sign in with phones 9000000001 (household), 9000000101 (vendor) or 9000000900 (admin) and code 123456. The demo buttons on the sign-in page only fill in the phone number.

Data is real, except admin. Household and vendor screens use the FastAPI backend and its SQLite database. Run npm run db:seed -- --reset to start again. Admin pages still show sample data, and say so, because the backend has no admin API yet.

How a page works

Every screen follows the same path. A route file stays thin, the task folder does the work, and one setting decides whether data comes from the mock or the real API.

src/routes/paths.tsEvery URL is defined here
↓
src/app/…/page.tsxNext.js route: checks the role, then renders a task's page
↓
src/tasks/<task>/ui/The screen the user sees
↓
src/tasks/<task>/api.tsCalls the API and maps its response
↓
mock.tsUsed by unit tests and admin pages
shared/api/client.tsUsed by the app. Calls the FastAPI backend

Every task folder has the same four parts

FileJob
api.tsThe endpoints this task calls
mock.tsThe same functions with sample data
types.tsThe shapes of this task's data
ui/Screens and components, with their tests beside them

User flows

Together these make the request → quote → accept path, worth 30% of the judging score.

Household: post a request

  1. Sign in with phone and OTP. A code is valid once, for 5 minutes and 5 attempts. tasks/auth/ui/LoginPage.tsx · POST /auth/otp, POST /auth/verify
  2. See my requests. The list shows only this household's requests. tasks/my-requests/ui/MyRequestsPage.tsx · GET /requests/mine
  3. Pin the home with the device location, an address search or a map click, then drag the pin onto the roof. Satellite view helps find it. tasks/new-request/ui/MapPicker.tsx, tasks/new-request/location.ts
  4. Speak the requirement (optional) in English, Hindi or Gujarati. The browser turns speech into text, the app reads the numbers from it, and the household checks the form. Nothing posts by itself. tasks/voice-input/ui/VoiceInput.tsx, tasks/voice-input/speech.ts, tasks/voice-input/parse.ts
  5. Enter usage, budget and roof area, and add a terrace photo. tasks/new-request/ui/NewRequestPage.tsx · POST /uploads
  6. Post and see the estimate: size, subsidy, cost, saving and payback, each with its working and source. tasks/rule-sources/ui/EstimateCard.tsx, tasks/rule-sources/ui/RuleSource.tsx · POST /requests, GET /rules/current

AI: terrace photo check

  1. The page shows "AI review in progress". The estimate stays usable meanwhile. tasks/roof-assessment/ui/RoofAssessmentPanel.tsx
  2. The page checks every 2 seconds until the result arrives. GET /requests/{id}/assessment
  3. Obstruction boxes appear over the photo, with usable area and the roof's kW limit. If the AI fails, only this panel changes.

Vendor: send a quote

  1. See open requests on the map. The location is rounded to about 500 m, and no phone number is shown. tasks/vendor-map/ui/VendorMapPage.tsx, tasks/vendor-map/ui/RequestsMap.tsx · GET /requests/open?bbox=
  2. Pick a request from the map or the list beside it.
  3. Fill in the quote: price, panel, inverter, warranty, timeline and what is included. tasks/quote-form/ui/QuoteFormPage.tsx · GET /vendor/requests/{id}, POST /requests/{id}/quotes
  4. The request becomes "Quotes received" for the household.

Household: compare and accept

  1. Compare quotes side by side, as a table on desktop and cards on a phone. Best values are marked. tasks/compare-quotes/ui/QuoteComparison.tsx · GET /requests/{id}/quotes
  2. See problems: missing items, non-DCR panels, a system bigger than the roof, and a warning on any quote with hidden AI instructions.
  3. Get a recommendation. The ranking comes from code, and the AI only writes the reasons. tasks/recommendation/ui/RecommendationCard.tsx · POST /requests/{id}/recommendation
  4. Accept one quote and confirm on the page. The other quotes are declined. POST /quotes/{id}/accept
  5. Contact details open up. The household sees the vendor's phone, and the vendor sees the household's phone and exact location.

Admin: run the marketplace

  1. Watch the dashboard: totals, trends, and alerts for work waiting. tasks/admin/ui/AdminPage.tsx, tasks/admin/ui/charts.tsx · GET /admin/overview
  2. Manage requests: search, filter, export to CSV, and cancel an active request. tasks/admin/ui/AdminRequestsPage.tsx
  3. Manage vendors: verify, reject, suspend or reinstate. A suspended vendor cannot sign in. tasks/admin/ui/AdminVendorsPage.tsx
  4. Review flagged quotes: see the hidden text, mark it reviewed, or suspend the vendor. Each action goes in the activity log. tasks/admin/ui/AdminReviewPage.tsx

Who calculates what

The brief requires subsidy, cost and payback to be calculated in code, and never guessed by the LLM. The UI only displays them.

OutputComes fromStatus
Size, subsidy, paybackrules/ through the APILive
Missing items, warningsrules/checklist.py through the APILive
Scores and rankingrules/scoring.py through the APILive
Photo findingsGemini visionNot built
Spoken textBrowser speech recognitionLive. Groq Whisper can replace it
Fields from speechtasks/voice-input/parse.tsLive
Recommendation reasonsLLM, from the score table onlyNot built

Tests hold the mock to the same golden example as rules/tests/test_golden.py: 330 units, 3 kW, ₹78,000 subsidy, ₹25,740 saved a year, 4.2 year payback.

Connection to the API

Every task's api.ts calls the real API and maps its response in one place, so screens never see the raw format. Types come from api/openapi.json. After the backend contract changes, run npm run api:types in ui/, and any mismatch shows up as a type error.

AreaStatus
Login, requests, uploads, map, quotes, accept, rulesReal API
RankingReal API scores from rules/
Recommendation reasonsNot built The endpoint returns 501, so the top score shows with no reasons
Photo assessmentNot built The page says AI review is unavailable
Hidden instruction warningNot built The backend always reports none. Scoring still ignores notes
VoiceBrowser speech recognition. /voice/transcribe returns 501
Admin pagesSample data The API has no /admin routes

The mock.ts files now serve unit tests and the admin pages only.

Keeping this updated

When you add, move or delete a file in ui/src, update this page in the same change. src/routes/guide.test.ts fails if this page names a file that doesn't exist, or leaves out a source file.
