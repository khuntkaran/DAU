SELC Hackathon · AI rooftop solar marketplace · data model

SuryaSetu database schema

Every table needed for the 22 mandatory features, the 3 bonus features and all recommended extras in the feature list. Each table is tagged with its build priority (P0–P3) and the features it serves. Subsidy, cost and payback results are stored with the rule rows they were calculated from, so the app can always show where a number came from.

ArchitectureSeven domains

The schema is split into domains that map to backend modules. files and ai_jobs are shared by every domain: any uploaded file is one row in files, and every LLM call is one row in ai_jobs.

IntegrityKeys, constraints and indexes

Business rules enforced by the database

ConstraintWhy
UNIQUE quotes(request_id, vendor_id)One quote per vendor per request. Revisions update the row and bump revision.
UNIQUE quotes(request_id) WHERE status='accepted'A request can never have two accepted quotes, even if two clicks race.
UNIQUE installation_projects(request_id)One installation per accepted request.
UNIQUE vendor_reviews(project_id)One review per completed installation, and only after one exists.
UNIQUE vendor_leads(vendor_id, request_id)One lead row per vendor per request.
UNIQUE rule_items(rule_set_id, rule_key, applies_to)Each rule appears once per version.
CHECK vendor_reviews.rating BETWEEN 1 AND 5Valid ratings only.
CHECK monthly_units > 0 AND budget_inr > 0The sizing and payback maths needs positive inputs.
CHECK calculations.quote_id IS NOT NULL WHEN scope='quote_financials'Quote financials always belong to a quote.

PortabilityLocal vs production

The same schema runs on SQLite for the hackathon demo and on PostgreSQL + PostGIS at state scale. Use SQLAlchemy so that switching is a change to DATABASE_URL.

Type in this schemaLocal: SQLiteProduction: PostgreSQL 16 + PostGIS

vendor_stats viewPlain viewMaterialized view refreshed every 15 minutes
llm_usageTable, single processMoved to Redis token buckets; the table keeps daily totals for cost reports
PartitioningNot neededai_jobs, notifications, audit_logs partitioned by month and archived after 12 months

Files are never stored in the database. files.storage_key points to a path in the local uploads/ folder during the demo, or to an object key in S3 / Cloud Storage in production.
